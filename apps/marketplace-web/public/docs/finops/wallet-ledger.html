内部虚拟钱包与只追加账本规范 ​

版本：v2.0.0 (企业级生产规范)
状态：已定稿 (Approved Specification)
适用范围：控制面管理系统、Go Gateway 数据面、消费与充值对账模块

1. 目标与范围 ​

为了解决企业智能体高频微计费与精细化预算控制，AgentPay 支持平台内部虚拟钱包（Internal Virtual Wallet）与只追加账本：

  • 用户/租户无需繁琐的逐笔外部结算，可直接通过内部虚拟钱包账户余额极速微计费扣除；
  • v1 核心范围：租户账户体系、只追加不可变流水账本（Append-Only Ledger）、冻结（Hold）/ 确认扣费（Capture）/ 释放（Release）机制、法定货币充值渠道抽象、日终/准实时自动对账；
  • v1 明确范围外：v1 明确不支持提现（No Withdrawal）、不支持用户间相互转账、不支持利息与跨币种兑换，以最小化金融合规与资金托管风险。

2. 核心架构决策（W1–W6 已拍定） ​

决策编号核心事项确定方案决策依据与安全考量
W1钱包归属层级租户级（Tenant-level）每个租户拥有且仅拥有一个主钱包账户。子项目（Project）不设独立子钱包，而是通过租户项目限额与部门配额树控制子项目额度，避免资金碎片化。
W2计价本位币与精度租户单一本位币 + 6 位微单位整数租户在注册/创建时选定单一本位法币（默认 CNY，支持 USD 或 EUR），初始化同币种主钱包且产生流水后永久锁定。内部账本统一固定 6 位小数精度（1 CNY/USD/EUR = 1,000,000 base units），全程严禁使用 float。
W3冻结超时 (Hold TTL)upstream_timeout + 60s默认 120 秒。必须覆盖上游 API 的最大超时时间加上网络安全抖动余量。
W4履约未知 (Unknown) 处理保持冻结并转 needs_review上游 5xx 或连接中断时，冻结保持锁定，既不自动扣费也不自动释放，防止恶意重试双花或白白损失服务。
W5支付方式选择与控制Challenge 协商，严禁透支API Key 首次请求取得 agentpay-wallet challenge；经客户端本地策略批准后重试进入钱包 Hold。钱包余额不足时直接返回 402 Insufficient Funds，严禁透支。
W6欠费与负余额处置欠费冻结（frozen_arrears）发生法币拒付或退款冲正致使余额为负时，账户状态变更为 frozen_arrears，系统拒绝一切新 Hold 请求，直至充值补足。

3. 数据模型定义 ​

3.1 钱包主账户 (Wallet) ​

每个租户全局唯一的资金容器。

字段类型约束说明
wallet_idVARCHAR(64)PK钱包唯一标识（wal_...）
tenant_idVARCHAR(64)UNIQUE, NOT NULL归属租户 ID
assetVARCHAR(16)NOT NULL租户选定的本位币代码（默认 CNY，支持 USD、EUR）
statusVARCHAR(32)NOT NULLactive（正常）、frozen（管理员冻结）、frozen_arrears（欠费冻结）、closed（注销）
versionBIGINTNOT NULL乐观锁版本号（并发控制）
available_cacheBIGINTNOT NULL可用余额缓存（以流水重新计算为准）
held_cacheBIGINTNOT NULL冻结金额缓存（以状态为 held 的 Hold 之和为准）
created_atTIMESTAMPTZNOT NULL创建时间（带时区时间戳）
updated_atTIMESTAMPTZNOT NULL更新时间（带时区时间戳）

3.2 只追加账本流水 (LedgerEntry) ​

不可修改、不可删除的不可变金融流水底账。

字段类型约束说明
entry_idVARCHAR(64)PK流水唯一标识（ent_...）
wallet_idVARCHAR(64)FK, NOT NULL归属钱包 ID
tenant_idVARCHAR(64)NOT NULL归属租户 ID
typeVARCHAR(32)NOT NULLtopup_credit（充值入账）、capture（扣费入账）、hold_release（解除冻结）、adjustment（管理员调账）、reversal（冲正回滚）
amountBIGINTNOT NULL变动金额整数（正数增余额，负数减余额）
idempotency_keyVARCHAR(128)NOT NULL同一钱包内唯一约束，防止重复记账
ref_typeVARCHAR(32)NOT NULL关联对象类型（TopUpOrder、PaymentIntent、Hold）
ref_idVARCHAR(64)NOT NULL关联业务 ID
operator_idVARCHAR(64)NULL操作者 ID（人工调账时必填）
reasonTEXTNULL调账原因说明（人工调账时必填）
created_atTIMESTAMPTZNOT NULL记账时间（带时区时间戳）

3.3 资金冻结凭单 (Hold) ​

请求生命周期内的临时配额锁定凭单。

字段类型约束说明
hold_idVARCHAR(64)PK冻结唯一标识（hld_...）
wallet_idVARCHAR(64)FK, NOT NULL归属钱包 ID
payment_intent_idVARCHAR(64)UNIQUE, NOT NULL绑定的支付意图 ID
amountBIGINTNOT NULL冻结金额（最小单位正整数）
statusVARCHAR(32)NOT NULLheld（冻结中）、captured（已扣款）、released（已全额释放）、expired（已超时过期）
expires_atTIMESTAMPTZNOT NULL冻结到期时间（带时区时间戳）
created_atTIMESTAMPTZNOT NULL创建时间（带时区时间戳）

3.4 统一充值单 (TopUpOrder) ​

三类充值渠道共用的充值凭证。外部法币充值（fiat）入账时，按 $\text{amount} = \text{payment_minor_amount} \times 10^{6 - \text{iso_decimals}}$ 转换为钱包 6 位微单位整数。

字段类型约束说明
topup_idVARCHAR(64)PK充值单唯一标识（top_...）
wallet_idVARCHAR(64)FK, NOT NULL充值目标钱包
tenant_idVARCHAR(64)NOT NULL租户 ID
channelVARCHAR(32)NOT NULLadmin_grant（管理员发放）、fiat（微信/支付宝线上充值）、bank_transfer（企业对公转账）
amountBIGINTNOT NULL入账钱包金额（6 位微单位正整数）
assetVARCHAR(16)NOT NULL入账本位币种（CNY、USD、EUR，与 Wallet.asset 一致）
payment_currencyVARCHAR(16)NULL外部渠道实际支付币种（如微信/支付宝 'CNY'、Stripe 'USD'）
payment_minor_amountBIGINTNULL外部支付渠道原始最小单位金额（如人民币“分”或美元“Cent”）
statusVARCHAR(32)NOT NULLcreated、pending、confirmed、failed、expired、reversed
external_refVARCHAR(128)NULL微信/支付宝流水号或企业银行对公打款流水凭证号
created_atTIMESTAMPTZNOT NULL下单时间（带时区时间戳）

4. 核心记账法则与安全不变量 ​

  1. 可用余额守卫 (Non-Negative Available Invariant)：
    • 任何时刻：available = 累积入账总额 - 累积确认扣款总额 - 当前 held 总额。
    • 发起 Hold 冻结时，必须验证 available >= request_amount；若不足则立即拒绝。
  2. 账本只追加 (Append-Only Invariant)：
    • LedgerEntry 严禁任何 UPDATE 或 DELETE 操作；更正历史错误必须通过生成 reversal 或 adjustment 的新流水追加实现。
  3. 强幂等记账 (Idempotency Invariant)：
    • 同一 idempotency_key 在相同 wallet_id 范围内只能有一笔有效流水，重复请求直接返回初次记账记录。
  4. 强行级锁 / 条件版本更新 (Concurrency Control)：
    • 生产数据库（PostgreSQL）执行余额冻结与扣款必须使用行级悲观锁：
      sql
      SELECT * FROM ap_wallet WHERE wallet_id = $1 FOR UPDATE;
    • 或者使用严格条件更新版本号：
      sql
      UPDATE ap_wallet 
SET available_cache = available_cache - $amount, held_cache = held_cache + $amount, version = version + 1 
WHERE wallet_id = $1 AND available_cache >= $amount AND version = $current_version;

5. 钱包支付完整链路与状态流转 ​

6. 充值渠道三阶段推进策略 ​

阶段渠道核心业务流防范风险与合规边界
Phase 1 (v1)管理员核拨 (admin_grant)具备管理员权限的角色通过控制台录入预算划拨，系统立即写入 topup_credit 流水必须强制记录 operator_id 与 reason，纳入审计日志，防止越权与滥发。
Phase 2 (v1.x)企业法币预付 (fiat)接入微信支付/支付宝企业收银台，扫码完成人民币预付款，Webhook 异步入账回调严格验签；双层幂等防重复；若发生冲正，触发 reversal 流水。
Phase 3 (未来)对公汇款与银企直联 (bank_transfer)企业财务公对公银行汇款，上传银行电子回单，财务审核确认后写入账本凭单唯一哈希查重；核对开票企业税号与抬头，支持一键开具数电发票。

7. 账本对账与五重一致性巡检机制 ​

系统定时任务（每小时/每日）自动执行五重对账平账检查：

  1. 流水余额重算核对：SUM(LedgerEntry) == Wallet.available_cache + Wallet.held_cache；
  2. 冻结单完整核对：所有处于 held 状态的 Hold 记录金额之和精确等于 Wallet.held_cache；
  3. 充值单一对一核对：每个状态为 confirmed 的 TopUpOrder 严格对应一条且仅一条 topup_credit 流水；
  4. 扣款与交付核对：每个 captured 的 Hold 严格对应一条结算记录与一条 2xx 履约记录；
  5. 僵尸冻结探测：now > expires_at 且依然处于 held 状态的记录为 0。

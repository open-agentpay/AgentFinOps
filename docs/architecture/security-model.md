# AgentFinOps 企业级安全与威胁模型规范 (N1–N6)

> **规范版本：** 2.0.0（企业级生产安全规范）  
> **核心定位：** **企业级 AI 行为审计与资金防火墙网关 (AI Agent Gateway & FinOps)**  
> **适用运行时：** AgentPay 核心网关运行时 (`gateway`)、多语言 SDK、控制台系统

---

## 1. 系统上下文与信任边界

AgentFinOps 运行在大语言模型（LLM）的非确定性推理与企业确定性财务资金、生产级商业 API 之间的安全防御边界上。

```text
┌────────────────────────────────────────────────────────────────────────┐
│                        UNTRUSTED ZONE (非授信区域)                     │
│   • 外部用户输入、提示词 (Prompt)、大模型生成的不可预测代码/工具调用   │
│   • 具备任意代码执行能力的本地/远程 Agent 宿主环境                     │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │ HTTP 请求 (携带 API Key / Approval Id)
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│                        TRUSTED ZONE (企业安全网关边界)                 │
│                                                                        │
│   ┌────────────────────────────────────────────────────────────────┐   │
│   │ 1. 身份与 RBAC 鉴权 (SHA-256 快速哈希校验，禁止明文落地)        │   │
│   │ 2. 金融防火墙策略预检 (单笔上限、24h 预算硬顶、滑动窗口 RPM)   │   │
│   │ 3. 树状配额级联校验 (租户 -> 部门 -> 项目 -> Agent)             │   │
│   │ 4. 人在回路 (HITL) 动态判定 (小额放行 / 中额审批 / 超额阻断)    │   │
│   │ 5. 原子三态记账引擎 (PostgreSQL 行级排他锁 Hold / Capture)     │   │
│   └────────────────────────────────────────────────────────────────┘   │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │ 安全内网专线 / 托管密钥
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│                     UPSTREAM RESOURCE (企业上游资源)                   │
│   • 商业大模型 (DeepSeek, 通义千问, 文心一言)                          │
│   • 商业付费数据源 (企查查, 万方数据, 金融量化数据)                    │
└────────────────────────────────────────────────────────────────────────┘
```

### 实体授信级别定义

| 实体 | 授信级别 | 理由与安全假设 |
| :--- | :--- | :--- |
| **LLM / 模型推理结果** | ❌ **非授信** | 存在提示词注入（Prompt Injection）、幻觉（Hallucination）及逻辑死循环可能；**严禁**直接触发无限制付款。 |
| **Agent 本地客户端** | ⚠️ **受限授信** | 运行策略引擎前端做快速熔断；但其行为必须受后端网关的强制二级校验约束。 |
| **企业安全网关 (Gateway)** | 🛡️ **高授信** | 独立于应用进程运行，严格执行四级配额校验、402 异步挂起、三态记账与行为黑匣子记录。 |
| **上游商业 API / 模型服务** | ⚖️ **外部依赖** | 存在网络超时、宕机或返回错误码的风险；网关负责通过三态机制保证资金不发生悬挂。 |

## 2. 企业核心威胁模型与防御策略 (N1–N6)

```text
┌────────────────────────────────────────────────────────────────────────┐
│                        企业级 AI 网关六大核心威胁矩阵                  │
├───────┬──────────────────────────┬─────────────────────────────────────┤
│ 威胁  │ 威胁表现与攻击路径       │ AgentFinOps 生产级防御方案          │
├───────┼──────────────────────────┼─────────────────────────────────────┤
│ **N1**│ 凭证泄露与密钥篡改       │ KMS / 国密 HSM 硬件隔离，内存零明文 │
│ **N2**│ 凭据重放与重复扣费       │ Nonce 机制 + 双层唯一幂等键         │
│ **N3**│ Agent 死循环刷爆预算     │ 本地内存 + 网关双重滑动窗口 RPM 熔断│
│ **N4**│ 上游网络超时与资金悬挂   │ Hold / Capture / Release 三态状态机 │
│ **N5**│ 部门与项目越权穿透预算   │ 租户/部门/项目/Agent 四级树状级联锁 │
│ **N6**│ 宿主进程被提权与内存篡改 │ 进程外独立 Sidecar 守护进程 (UDS)   │
└───────┴──────────────────────────┴─────────────────────────────────────┘
```

### N1：凭证泄露与密钥篡改风险
* **威胁描述**：开发者将上游商业 API Master Key 或网关凭据明文写在代码、配置文件或环境变量中，遭 Prompt 泄漏或代码泄露。
* **防御机制**：
  1. 上游 Master Key 集中托管在网关后端数据库，采用 AES-256-GCM 加密存储；
  2. 生产环境支持直连阿里云 KMS、腾讯云 KMS、AWS KMS 或金融级国密硬件加密机（HSM），密钥永不以明文形式暴露在磁盘或环境变量中。

### N2：凭据重放与重复入账风险
* **威胁描述**：攻击者截获已通过的审批凭证（`approval_id`）或充值 Webhook，重放发起二次扣款或重复入账。
* **防御机制**：
  1. 审批凭证签发严格绑定随机 Nonce 与 300 秒有效期窗口；网关在消费审批单时执行原子 CAS（Compare-And-Swap）更新，状态转为 `consumed`，重复使用立即拒绝；
  2. 外部在线充值 Webhook 采用 `external_ref`（微信/支付宝交易号）与 `topup_id` 建立组合唯一索引，重复通知严格幂等跳过。

### N3：Agent 陷入死循环刷爆预算风险 (Runaway Loop)
* **威胁描述**：智能体由于提示词冲突或代码递归陷入无限调用，数分钟内消耗数万元调用额度。
* **防御机制**：
  1. **端侧毫秒级拦截**：Client SDK 本地内置轻量策略引擎，滑动窗口监控调用频次，达到 RPM 上限立即将状态置为 `OPEN`，本地阻断网络请求；
  2. **网关硬顶兜底**：网关核心维持分布式滑动窗口计量，命中熔断阈值强制阻断并向负责人企业微信/飞书告警。

### N4：上游超时与网络抖动导致资金悬挂风险
* **威胁描述**：网关向上游发起调用后，因网络超时未收到响应，导致无法判断是否该扣款，造成“资金被冻结但无法释放”或“重复扣费”。
* **防御机制**：
  1. 严格采用 **Hold $\to$ Capture $\to$ Release** 三态事务状态机；
  2. 调用前仅锁定预估配额（Hold）；若上游返回 504 Gateway Timeout 或连接断开，后台调度器原子触发 Release，100% 解除冻结额度，资金原路返还，绝无悬挂订单。

### N5：部门与项目越权穿透预算风险
* **威胁描述**：某边缘实验项目的智能体消耗超过其项目配额，意外穿透刷透其他业务部门乃至企业总账户余额。
* **防御机制**：
  1. 网关在每个请求入口严格执行**四级树状级联校验**：
     $$\begin{cases}
     \text{Agent.spent}_{24h} + \Delta \le \text{Agent.daily\_budget\_cap} \\
     \text{Project.spent}_{month} + \Delta \le \text{Project.monthly\_budget\_cap} \\
     \text{Department.spent}_{month} + \Delta \le \text{Department.monthly\_budget\_cap} \\
     \text{Tenant.available\_balance} \ge \Delta
     \end{cases}$$
  2. 任何下级超出即刻阻断，报错精确定位，保证不同部门间配额绝对物理隔离。

### N6：宿主进程被提权与内存篡改风险
* **威胁描述**：智能体运行具备任意代码执行能力（如 Python `exec` 或 Shell 执行），恶意工具直接读取同进程内存中的策略配置或篡改 SDK 拦截器逻辑。
* **防御机制**：
  1. 将策略引擎与金融防火墙下沉为独立的**本地 Sidecar 守护进程**；
  2. 守护进程以受限的独立 OS 用户运行，主 Agent 仅能通过本地 Unix Domain Socket (UDS) 或 IPC 与防火墙通信，物理隔离宿主内存空间。
